# FLOWS.md — 流程契约（Source of Truth）

> **本文件的 `flow` 块是解析目标**，与状态写入点做**双向**对拍。
> 破坏格式 / 声明与实现不符 = **测试红**（`{{校验命令}}`，已挂进 `{{默认测试命令}}`）。
>
> 关联：[`DOMAIN.md`](DOMAIN.md)（枚举取值）· [`DECISIONS.md`](DECISIONS.md)（INV 在册）·
> [`ARCHITECTURE.md`](ARCHITECTURE.md)（分层）。
>
> **只写事实**：`impl: yes` = 代码里真有这条转移；`impl: no` = **枚举里有这个状态但没人写它**。
> 后者不是遗漏登记，是**待办或死值**，逐条在末节给出处置。
>
> **`impl` 是状态级语义，不是转移级。** 改任何状态写入前先读对应 `flow` 块。

## 0. 契约格式

每台状态机一个 ```flow 块：

```
machine: <对象>.<状态字段>
enum:    <枚举名>
states:  [<全部取值，须与 DOMAIN.md §1 一致>]
initial: <插入时的初值>
- <from> → <to> | via: <入口> | by: <触发者> | inv: <INV-n 或 -> | impl: yes|no
```

**四要素缺一不可**：`via`（唯一合法入口）· `by`（谁能触发）· `inv`（受哪条不变量约束）· `impl`（是否已实现）。
`from` 为 `*` 表示任意状态；`by: system` 表示无人工触发（worker / 调度器）。

> **凡有状态字段的对象都必须登记一台状态机**，不得只登记"主要的几条"——
> 漏一台等于给智能体留一片无契约区。

## 附录：格式契约（校验器解析规则）

1. 每个 `flow` 块须含 `machine` / `enum` / `states` / `initial` 四个头字段。
2. 每条转移行须五段齐全：`from → to` + `via` + `by` + `inv` + `impl`；缺任一段即红。
3. `states` **==** 对应枚举取值集合（与 DOMAIN.md 一致）。
4. 每条转移的 `from` / `to` **∈** `states`。
5. **`impl` 双向（状态级语义）**：
   - `impl: yes` 的目标态 → 代码中须存在写入点；
   - `impl: no` 的目标态 → 代码中须**不存在**写入点；
   - 同一目标态被同时声明 `yes` 与 `no` → **红**（矛盾声明）。
6. `via` 可解析：API 路由须能在入口层定位；`scheduler:X` 须能定位符号 `X`。
7. `impl: no` 的状态须在"未实现状态的处置"节有条目。
8. **任一 `flow` 块解析为 0 行转移 = 格式契约破坏 = 红。**
